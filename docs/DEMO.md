# 5～10 分钟项目演示

演示文件：[recruiting_sales.csv](../demo_data/recruiting_sales.csv)。它是 12 行、5 个字段的虚构销售数据，日期为 2026-10-01 至 2026-10-03。所有邮箱均为 `demoNN@example.com` 模拟值，不包含真实用户信息。金额统一按“元”讲解。原有 `sample_sales.csv` 保留，合计仍为 400.00。

基础路线约 5 分钟，不调用模型；已配置千问时再加 3～5 分钟展示 Agent。敏感操作和重启恢复可作为加时项目。本文给出操作预期，不代表已完成真实模型或浏览器验收。

## 演示前准备

1. 使用已有虚拟环境和已有本机账户。没有账户时按 [README](../README.md) 的首次初始化说明操作；本演示包没有创建账号、密码或 API Key。
2. 在项目根目录的 PowerShell 运行：

   ```powershell
   .\.venv\Scripts\python.exe run_local.py --check
   .\.venv\Scripts\python.exe run_local.py
   ```

3. 打开 `http://127.0.0.1:8501`，在“登录数析”填写“用户名”“密码”，点击“登录”。普通统计可用分析员；敏感预览和全量 CSV 演示须用管理员。
4. Agent 路线要求启动应用的环境已配置有效 `DASHSCOPE_API_KEY`，接口地址与账号地域匹配，且可调用 `qwen-plus`。不要把密钥粘贴到问题、文档或共享屏幕中。上传演示数据后直接提交分析问题；如果连接异常，页面会显示提示。
5. 没有已配置的模型或连接失败时，直接走基础路线。不要为了演示新增外部服务或展示预制的“模型成功结果”。

## 路线 B：已配置模型后增加 3～5 分钟

1. 在“多步 Agent”保留“敏感字段（可补充勾选）”中的“邮箱”；不将“商品”或“日期”另标为敏感，否则相应分组或趋势会隐藏。
2. 在“请输入多步分析问题”粘贴：

   > 先查看字段，再统计全部销售记录的条数、销售额总和和平均值，然后按日期汇总，最后选择柱状图。请根据工具返回结果说明结论。

3. 点击“开始 Agent 分析”。结束后查看 `trace_id`、结构化计划、回答与“Agent 选择图表”。预期涉及 `schema_inspect`、`sales_summary`、`daily_sales_summary`、`sales_chart`，图表类型为 `bar`。数值应与上表一致；字段工具返回 12 行与非敏感字段，邮箱取值不会作为工具结果发给模型。
4. 复制本次 `trace_id`，回到页面上方“按 trace_id 查看分析过程”，粘贴后点“查看 Trace”。查看步骤表并展开计划、工具和回答，核对风险原因、统计摘要、状态、耗时及最终回答。历史展示不会重新执行工具，也不是模型内部思考记录。
5. 回到已完成的 Agent 结果，点击“下载分析报告 Markdown”。浏览器保存的文件名应为 `analysis-<trace_id>.md`；打开后核对本次问题、计划、统计值、日期汇总和图表说明。报告提供图表文字说明，不内嵌图像。浏览器下载仍须按文末清单人工验收。

结构化计划与实际工具调用顺序可能不同。只讲本次 Trace 中确实发生的调用，不宣称每次都会按上述顺序执行。若工具结果不足或数值不一致，应展示实际情况并停止作出统计结论。

可替换的简短问题：

| 输入位置 | 提问模板 | 可核对结果 |
| --- | --- | --- |
| “向数据提问” → “请输入关于销售额的问题” | 咖啡销售额合计是多少？ | 咖啡 580.00；保持“让模型建议工具”未勾选时走固定规则选择。该入口一次只问一个商品。 |
| “多步 Agent” → “请输入多步分析问题” | 查看字段，然后统计销售额总和和平均值。 | 12 行、1,800.00、150.00。 |
| “多步 Agent” → “请输入多步分析问题” | 按日期汇总销售额，说明哪一天最高。 | 10 月 3 日最高，为 850.00。需事先选择“日期”字段。 |

## 可选加时：拒绝、批准与敏感下载

需管理员、模型连接可用，且“邮箱”仍标为敏感。每个场景单独发起，方便说明审核边界。

1. **拒绝敏感预览**：输入“请预览邮箱字段的前 10 行。”，点击“开始 Agent 分析”。模型实际请求 `column_preview` 且参数为 `{"column_name":"邮箱"}` 时，页面显示“以下操作需要人工审核，批准前不会执行。”。记下 `trace_id`，点击“拒绝并结束”。应看到“已拒绝，本次工具链未继续执行。”，当前分析不会展示邮箱预览。查看本次 Trace 的拒绝状态。此前已执行的安全统计不会回滚。
2. **批准敏感预览**：重新发起同一问题，核对待审工具和参数后点击“批准并继续”。完成后，结果区应出现前 10 个模拟邮箱；页面普通数据预览仍按敏感字段规则遮挡。工具返回给模型的是准备状态、字段名与行数，原始邮箱值仅用于页面展示。
3. **批准全量 CSV**：输入“请导出当前文件的全部原始数据为 CSV。”。出现 `full_csv_export`、参数 `{}` 的待审请求后点击“批准并继续”。完成后点击“下载全部原始数据 CSV”，打开 `sales_full.csv`，核对 12 行、5 个字段、模拟邮箱、末两行 300/200 与总额 1,800。若出现后续待审请求，逐一核对实际操作再决定。

分析员不能批准敏感预览或全量原始数据导出。页面现在展示确定性规则计算的低风险、高风险或禁止执行及其原因；敏感预览和全量导出为管理员高风险操作。风险等级不表示模型自行批准。可额外把商品或销售额标为敏感，展示对应统计停止；演示后恢复原选择。

## 可选加时：重启恢复待审核请求

1. 管理员发起“请预览邮箱字段的前 10 行。”，在待审界面记录 `trace_id`，先不批准或拒绝。
2. 在启动应用的 PowerShell 窗口按 `Ctrl+C`。确认进程与服务关闭，再用同一个虚拟环境运行 `run_local.py`。键盘停机行为仍属待人工验收项。
3. 使用同一账户登录，重新上传**同一份未修改的 CSV**，恢复销售额列、日期列和敏感字段选择。不要点击“开始 Agent 分析”新建另一条分析。
4. 在“恢复待审核 trace_id”填入刚才记录的 ID，点击“恢复待审核”。恢复依赖原存储密钥、该用户的待办与检查点，以及仍可用的模型配置。
5. 核对恢复后的工具和参数，选择“批准并继续”或“拒绝并结束”，再查看对应 Trace。若提示文件或字段设置不一致，应纠正设置，不修改检查点文件来绕过检查。

这里演示的是待审 Agent 的检查点恢复。备份 ZIP 的创建、验证与恢复是另一个流程，见 [README](../README.md)。

## 失败时的讲解路线

模型无响应、配额不足、密钥不可用或计划未通过校验时，保留实际错误提示，停止该次 Agent 展示。继续核对基础统计和图表，再展示 `sales_tools.py` 的工具白名单与参数校验、`analysis_agent.py` 的审核流程、`trace_store.py` 的事件记录，以及 [当前差距](PROJECT_GAPS.md)。不伪造回答、计划、Trace 或已下载文件。

若真实下载失败，说明下载接口已实现但当前浏览器验收未通过，保留失败记录；不要把按钮出现或自动化通过当作浏览器保存成功。需要进一步讲解时查看 `secure_download.py` 与 `download_service.py` 的实际实现。
