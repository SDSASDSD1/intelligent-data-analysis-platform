## 3. 十二个核心面试问答

### 1）用户输入一句话后，系统具体做了什么？

先区分页面上的两个入口：

- “向数据提问”使用已计算的统计结果，默认按固定规则选择汇总或单商品查询，也可以让模型建议工具后再校验。
- “多步 Agent”先请求模型输出 JSON 计划；解析与校验通过后，再创建 Agent。Agent 接收问题和已校验计划，根据需要调用工具，最后产生回答或暂停等待审核。

数据来自当前上传的表格，金额由 Pandas 计算。页面负责展示、交互与下载。不能把所有功能都说成“模型自动完成”。

**看代码：** `app.py` 的 `main()`，搜索“向数据提问”“多步 Agent”。

### 2）你实现的是 ReAct 吗？循环是自己写的吗？

项目使用 LangChain `create_agent()` 提供的模型调用与工具调用循环：模型提出工具调用，程序执行工具，工具结果作为消息交回模型，模型再决定下一步。这可以称为 ReAct 风格的 Agent 流程。

循环由框架提供。项目代码负责工具封装、校验、调用次数限制、审核和页面衔接，没有手写 ReAct 调度内核，也没有训练大模型。系统提示词要求模型观察工具结果，但日志并不等于模型内部完整思考过程。

`ModelCallLimitMiddleware(run_limit=7)` 和 `ToolCallLimitMiddleware(run_limit=6)` 是 Agent 运行的调用限制。初始规划请求发生在创建 Agent 之前，不能因此说“一次用户请求最多只有七次模型请求”；审核恢复也应单独理解。

**看代码：** `analysis_agent.py` 的 `create_analysis_agent()`。

### 3）模型返回的内容不是规范 JSON，怎么办？

`parse_analysis_plan()` 先尝试 `json.loads(text)`。如果直接解析失败，再用正则 `r"\{.*\}"` 提取从左花括号到右花括号的候选内容，尝试第二次 JSON 解析。最终必须得到字典，否则返回 `None`。

随后还要检查结构、工具、参数和角色。任何校验失败，页面展示提示和模型原文本，本次不运行 Agent。

这不是完整的 JSON 修复器。正则是贪婪匹配，遇到多个 JSON 对象可能一起提取并解析失败；也没有自动修复字段、反复重试直到成功或在失败后继续执行。没有测量真实模型的格式成功率。

规划提示词另外提供了角色定位、当前字段与问题、固定输出结构以及一个格式示例。
它们用于引导输出；不能代替解析与参数校验，也没有现成的成功率提升数据。

**看代码：** `analysis_agent.py` 的 `parse_analysis_plan()`；`app.py` 中 `plan_valid` 的分支。

### 4）有了计划校验，为什么执行工具时还要校验？

因为计划和实际调用是两份可能不同的模型输出。计划通过校验后，被放进消息交给 Agent；当前实现没有逐条按照 `steps` 强制调度，也没有保证实际调用与计划一一对应。

因此，`guard_tool_call` 会在每次实际执行前重新检查工具名称、参数、角色权限和当前会话是否有效。即使模型后来提出了非法调用，也不会因为计划曾通过检查就自动放行。

如果要保证严格执行顺序，需要另行实现按计划推进的执行器或状态机。这是后续可讨论的改进，不是当前已实现的能力。

**看代码：** `validate_analysis_plan()`、`guard_tool_call`，以及 `app.py` 中 `agent.invoke()` 的消息。

### 5）有哪些工具？工具是不是让模型执行 Python？

基础工具如下：

| 工具名 | 作用 | 主要输入 |
| --- | --- | --- |
| `sales_summary` | 记录数、销售额总和与平均值 | 无 |
| `product_sales_total` | 查询一个已有商品的销售额合计 | 完整商品名称 |
| `schema_inspect` | 查看行数和非敏感字段名 | 无 |
| `sales_chart` | 选择柱状图或逐条折线图 | `bar` 或 `line` |
| `column_preview` | 准备页面上的指定列前十行预览 | 当前文件中的列名 |
| `full_csv_export` | 准备全部原始数据的 CSV 下载内容 | 无 |

有可用的按日汇总数据时，增加 `daily_sales_summary`。缺少商品列时仍注册商品工具接口，但实际校验不能通过没有数据依据的商品查询。

这些工具都是开发时写好的 Python 函数。模型只能提出工具名和参数，项目不执行模型生成的代码，也没有给模型开放任意文件访问或任意表达式执行入口。

**看代码：** `sales_tools.py` 中各个 `make_*_tool()` 和 `validate_agent_tool_call()`。

### 6）怎么保证统计不是模型猜出来的？只显示十行会不会漏算？

页面先读取整份 CSV 或 Excel 的第一个工作表，再把选中的金额列转换为数字。有无法转换的值时，停止这部分分析并提示用户。

`head(10)` 只用于预览。求和、平均值、分组和折线图使用完整数据。商品统计用 `groupby(...).sum()`，日期统计先解析日期并归到自然日，再按日求和。模型收到的是工具返回的统计值。

这能让统计值具有可复核的计算依据，但不能保证模型最终每一句解释都正确，也不能代替对业务口径的确认。例如，“平均值”当前指每条销售记录的销售额平均值，未必是业务里的客单价。

**看代码：** `app.py` 中 `pd.to_numeric`、`groupby`；`date_analysis.py` 的 `build_daily_sales()`。

### 7）什么操作需要人工审核？拒绝以后发生什么？

管理员请求预览已标记的敏感列，或者导出全量 CSV 时，`HumanInTheLoopMiddleware` 会触发暂停。敏感列由列名关键词建议和页面选择确定，属于明确规则，当前没有让模型自动给操作打风险分。

批准后通过 `Command(resume=...)` 继续。拒绝时，页面核对并取走待办、记录拒绝事件、清除当前待审核状态，结束这次流程；不会继续执行后续操作，也不会自动撤销此前已经完成的统计计算。

分析员无权执行敏感列预览和全量 CSV 导出；管理员身份也不意味着这些操作可以跳过审核。

**看代码：** `analysis_agent.py` 的审核中间件；`app.py` 中“批准并继续”和“拒绝并结束”。

### 8）服务重启后怎么恢复审核？为什么不能重复批准？

项目保存待审核元数据，并使用 SQLite 检查点保存 Agent 状态。恢复时需要同一用户重新上传相同内容的文件，并保持金额列、日期列和敏感列选择一致。

上传文件用 SHA-256 指纹核对；待办还核对用户、审核 ID 和待执行操作。处理时通过 `take_pending()` 原子取走当前待办，避免两个页面把同一份待办重复处理；每次新中断会产生新的审核 ID。

页面的 `st.session_state` 只负责当前页面状态，不能单独承担进程重启后的恢复。SQLite 检查点与待办记录才是恢复所依赖的持久化资料。

**看代码：** `app.py` 的 `save_review_pending()`、`review_matches_pending()`；`review_store.py`。

### 9）Trace 能不能重放整个分析？

当前 Trace 按 `trace_id` 展示问题、计划、工具、参数、风险、受控结果摘要、审核、耗时和脱敏最终回答，适合排查某一次分析经过了哪些步骤。它没有记录模型的全部输出和外部环境，也没有实现确定性的重新执行。

所以应说“过程追踪与查询”，不应说“确定性重放”。待审核任务的恢复依赖检查点，是另一种能力。

日志限制可写字段，写入前会按规则脱敏；正常登录流程还会传入加密器。关键词和格式规则仍有局限，不能据此声称所有敏感信息都绝不会泄露。

**看代码：** `trace_store.py` 的 `ALLOWED_FIELDS`、`summarize_tool_result()`、`redact()`、`read_trace()`；`trace_viewer.py`。

### 10）图表由模型生成吗？报告里有图片吗？

`sales_chart` 只校验 `bar` 或 `line` 并把选择写进 `artifacts`。实际图形由 `app.py` 中的 Matplotlib 代码绘制；页面会根据可用数据展示商品柱状图、逐条折线图及可选日期趋势图，不能说模型生成了任意图表代码。

逐条折线图的横轴是数据行序号；日期趋势图的横轴才是日期。两者不要混为一谈。

Markdown 报告包含问题、计划、统计结果、可用的汇总表、图表选择说明、回答和 `trace_id`。当前没有把图像嵌入报告，也没有实现 PDF 或 Word 报告导出。

**看代码：** `sales_tools.py` 的 `make_chart_tool()`；`app.py` 中 `Figure`；`report_export.py`。

### 11）有权限和加密以后，是否就完全安全？

当前实现了本机管理员/分析员角色、按用户分目录保存资料、敏感操作审核、下载时重新检查身份，以及分析资料的认证加密。密码使用带随机盐的 PBKDF2 派生结果验证，Fernet 用于需要再次读取的资料，两者用途不同。

模型不会由预览或导出工具拿到整份原始数据行；但仍会收到脱敏后的用户问题、规划阶段的字段名、部分工具参数和统计结果。文本规则无法识别所有私人信息，不能笼统承诺“没有任何数据离开本机”。

`risk_policy.py` 统一禁止敏感金额、商品和日期的对应派生统计。普通操作是低风险；管理员的敏感预览或全量导出是高风险，执行前暂停审核；分析员越权直接阻止。计划和真实调用都检查，界面展示等级和原因；遗漏开启审核的调用者也不能直接执行高风险工具。

`_looks_like_code()` 只是过滤部分代码关键词。工具白名单和参数校验缩小了可执行操作范围，仍不能当作全面的提示词注入防御。当前项目按本机多用户环境设计，未形成公网生产部署的安全验收结论。

**看代码：** `analysis_agent.py` 的 `tool_permitted()`；`auth_store.py`；`secure_storage.py`；`download_service.py`；`sales_tools.py` 的 `_looks_like_code()`。

## 5. 遇到这些 Python 写法时怎么理解

| 写法 | 通俗解释 | 本项目中的意义 |
| --- | --- | --- |
| `import pandas as pd` | 导入工具箱，并给它起短名字 | 后面用 `pd.read_csv()` 读取表格 |
| `def 函数名(...):` | 给一组操作起名字，方便重复调用 | `parse_analysis_plan(text)` 接收文字并返回解析结果 |
| `return` | 把结果交回调用者，并结束本次函数 | 返回 `None` 表示当前解析没有得到可用计划 |
| `dict`、`list` | 字典按名字找值，列表按顺序放多个值 | `{"steps": [...]}` 是字典，里面的步骤是列表 |
| `data["销售额"]` | 取表格的一列 | 得到 Pandas 的 `Series`，整张表是 `DataFrame` |
| `data.head(10).copy()` | 复制前十行，作为另一个展示对象 | 修改预览中的敏感内容，不直接改原表 |
| `x is None` | 判断是不是“还没有这个结果” | 没有分组表、没有日期汇总时走另一分支 |
| `try` / `except` | 尝试一个操作，处理指定类型的失败 | JSON 解析失败后尝试候选文本 |
| `with ... as ...` | 使用一个需要收尾的资源 | 读写文件结束时自动关闭文件 |
| `f"{total:.2f}"` | 把值填入文字，保留两位小数显示 | 控制页面和报告的金额显示格式 |
| `str`、`dict \| None` 类型标注 | 提示参数或返回值预期是什么 | 帮助阅读；标注本身不会自动拦住错误输入 |
| `all(...)` / `any(...)` | 分别判断“全部满足”和“至少一个满足” | 计划的每一步都必须通过校验 |
| `lambda: ...` | 写一个很短的小函数 | 工具调用前重新检查当前会话 |
| `st.session_state` | Streamlit 在页面重新运行之间保存的状态容器 | 暂存结果、选择项和待审核状态；进程重启恢复还要靠持久化 |

### 为什么函数里面还有一个函数？

以 `make_sales_summary_tool(sales)` 为例：

```python
row_count = len(sales)
sales_total = float(sales.sum())
```

外层函数先根据当前文件计算统计值，再定义里面的 `sales_summary()`，最后返回这个工具。内部函数可以继续使用外层准备好的 `row_count` 和 `sales_total`，这叫闭包。

可以把它理解成“给当前文件装好的一台查询器”：工具调用时没有金额参数，因为它已经绑定了这次上传的数据。换文件以后需要重新准备工具和结果，不能继续拿旧文件的统计回答。

### `@tool`、`@wrap_tool_call` 是什么意思？

`@...` 是装饰器写法，可以理解为“给函数加一层能力”：

- `@tool` 将普通函数包装成 LangChain 可描述、可调用的工具，提供工具名、说明和参数信息。
- `@wrap_tool_call` 将检查逻辑放到工具执行周围；通过校验才调用真正的处理器，随后记录状态和耗时。

知道装饰器的用途就可以开始读代码，不需要先自己实现一个装饰器框架。也不能因为写了 `@tool` 就认为所有输入自动安全，项目仍有显式参数检查。

### `artifacts` 和工具返回值有什么区别？

`artifacts` 是页面与工具共享的字典。例如，预览工具把表格放到 `artifacts["column_preview"]`，返回给模型的只是准备完成状态、列名和行数。

它把“页面要显示的内容”和“模型要观察的结果”分开。完整 CSV 也放在页面使用的结果字典里，而不是作为工具消息把原始文件内容发送给模型。

## 6. 距离“能写简历、能经得起追问”还差哪些

| 目标表述 | 当前依据或差距 | 下一步怎样形成证据 |
| --- | --- | --- |
| 能完整展示销售分析项目 | 核心功能已有代码，完整浏览器演示仍需实际完成 | 用示例文件走通上传、提问、审核、Trace 和报告，保留脱敏截图或录屏 |
| 能解释自己的贡献 | 功能存在不等于个人已经掌握 | 每条简历职责对应一个自己读懂的函数和一个真正解决过的问题 |
| 能说模型表现稳定 | 缺固定问题集上的真实模型统计 | 记录问题、预期工具、实际计划、答案依据和失败原因，再计算有分母的指标 |
| 严格按计划执行 | 当前计划只是发给 Agent 的消息 | 若目标确实需要该能力，再设计逐步执行及偏离计划的处理规则 |
| 报告包含图像 | 当前 Markdown 只有图表说明 | 若岗位演示需要，再增加图像导出及报告引用，并检查最终文件 |
| Trace 确定性重放 | 当前是历史步骤与结果展示 | 先明确重放所需的输入、模型响应和环境记录，不把历史展示当作重新执行 |
| 敏感信息全部自动识别 | 已有统一统计策略和发送前脱敏，但识别有边界 | 讲清列名识别、人工标记与文本规则各自能覆盖的情况 |
| 企业生产级或全面安全 | 当前按本机多用户场景实现和验收 | 另行设计部署、认证、密钥管理、监控和安全评估；当前简历保持本机项目定位 |

对当前阶段，优先完成“讲明白一条完整数据流”和“实际演示一次”。能准确说出工具为什么允许执行、拒绝时会怎样，比增加更多尚未理解的功能更有助于面试。
